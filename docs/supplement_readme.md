# Evidence Attribution in Visual Document Understanding without Coordinates or Region Labels

Anonymous supplementary code for the ARR submission.

This archive contains the code that produces the numbers in the paper: the two evidence
interfaces, the quote-to-region retrieval pipeline, the scorer, all control experiments, and
the region-label-free GRPO reward. It also contains a small synthetic example so that the
scoring and control code can be run immediately without downloading any documents.

Absolute paths, cluster names, account names, and environment names have been replaced by
placeholders (`${PROJECT_ROOT}`, `${ENV_MAIN}`, `<PARTITION>`, `<ACCOUNT>`). Set them for your
own system before running the batch scripts.

## 2. Run the example immediately (no downloads, CPU only)

The two example files contain four synthetic questions in the exact record format the pipeline
uses. They are hand-written, not drawn from any benchmark, and exist only to make the code
runnable and the record schema self-documenting.

```bash
python src/score_citevqa.py examples/sample_predictions.jsonl
python src/score_citevqa.py examples/sample_predictions_coordinate.jsonl
```

The first prints recall 62.5, precision 83.3, page recall 75.0; the second prints the same
questions scored under the coordinate interface, where two of the four boxes miss at IoU 0.5
even though one of them lands on the correct page. This is the paper's central contrast in
miniature: identical answers, different evidence interface, different attribution score.

### Record schema

Each line is one question:

| field | meaning |
|---|---|
| `index` | question identifier |
| `question`, `standard_answer` | from the benchmark |
| `gt_necessary` | necessary evidence elements, `[page, x1, y1, x2, y2]`, used for recall |
| `gt_all` | all annotated elements including optional ones, used for precision |
| `raw_predict` | the model's raw output, JSON with quotes under the language interface, inline boxes under the coordinate interface |
| `answer_text` | the parsed answer |
| `pred_tuples` | the scored citations, `[doc_id, page, x1, y1, x2, y2]` |
| `format_ok` | whether a parseable citation was produced |

Under the coordinate interface `pred_tuples` comes straight from the model's own numbers.
Under the language interface it is produced by `match_wholedoc.py` from the model's quotes;
the model itself never emits geometry.

## 3. Reproducing the paper

Steps 1 and 2 need the public document corpus; steps 3 to 5 need GPUs.

**1. Build the verified evaluation set.**
```bash
python src/build_citevqa_pub.py     # applies the filtering funnel, 987 -> 719 questions
python src/build_citevqa_eval.py    # assembles ground-truth tuples per question
```

**2. Parse documents and cache block embeddings.** One layout parse and one crop embedding per
block, cached per document and amortized across that document's questions.
```bash
python src/prebuild_block_emb.py
```

**3. Run the interface comparison.** One job per backbone and interface.
```bash
sbatch slurm/matrix_backbone.sh    # sets the interface via an environment variable
python  src/match_wholedoc.py      # language interface only: quotes -> regions
python  src/score_citevqa.py outputs/matrix/<condition>/predictions.jsonl
```

**4. Judge-based metrics.**
```bash
python src/build_judge_batch.py && sbatch slurm/judge_batch.sh
python src/score_judge_batch.py    # SAA and AH
python src/build_main_table.py     # the main results table
```

**5. Control experiments.** All controls reuse the frozen outputs from step 3 and require no new
inference except the embedding job.
```bash
python src/controls_rereview.py snap        # coordinate boxes snapped to blocks
python src/controls_rereview.py funnel      # filtering funnel and dropped-document analysis
python src/controls_rereview.py stats       # paired bootstrap and McNemar
python src/controls_rereview.py precision   # citation precision and citations per response
python src/controls_rereview.py breakdown   # per-language and per-evidence-type
sbatch slurm/controls_embed.sh              # retrieval-only baselines, resolver ablation, abstention
python src/resolver_ablation.py             # lexical and BM25 resolvers, quote fidelity
sbatch slurm/docling_parse.sh && sbatch slurm/docling_match.sh   # independent-parser check
```

**6. Training.** Region-label-free GRPO; the reward reads the gold answer and crops of the
retrieved regions, never a region label.
```bash
python src/build_grpo_longdoc.py    # training questions from the long-document corpus
sbatch slurm/serve_judge.sh         # reward judge
sbatch slurm/grpo_longdoc_chain.sh  # chained training jobs
```

## 4. Scoring protocol implemented here

`src/score_citevqa.py` is the single scoring path used by every experiment, so all conditions
are measured identically.

A cited box matches an annotated element when the two lie on the same page and their IoU is at
least 0.5. Recall is computed per question as the number of necessary elements matched by at
least one citation divided by the number of necessary elements, then macro-averaged over
questions. Precision replicates the loop of the scorer released with the benchmark: the
numerator counts annotated elements that some citation hits, and the denominator is the number
of boxes cited, so the two range over different objects. Two protocol choices are ours and are
applied identically to every condition: recall is scored against necessary evidence while
precision is scored against all annotated evidence including optional supporting elements, and
citations are scored against whichever page the model names, without correcting page indices.

## 5. Environment

```bash
pip install -r requirements.txt
```

External services and models used, all cited in the paper: a layout parser and an independent
second parser for the cross-parser check, a multimodal embedding model for retrieval, an
open-weight vision-language model as the training reward judge, and a commercial API model as
the evaluation judge. Set the judge API key in the environment before running step 4.

Compute reported in the paper: approximately 85 GPU-hours for training, approximately 60
single-GPU-hours for the thirteen-condition evaluation matrix, and under two GPU-hours for the
diagnostic analyses.
