# Data format

Every stage of the pipeline reads and writes JSONL, one JSON object per question. The same
record type flows from inference through matching to scoring, which is what lets the coordinate
and language conditions share a scorer.

Two worked examples ship with the repository, describing the same four questions under each
interface:

- `examples/sample_predictions.jsonl` — language interface
- `examples/sample_predictions_coordinate.jsonl` — coordinate interface

They are hand-written and contain no benchmark content.

## Fields

| field | type | written by | meaning |
|---|---|---|---|
| `index` | string | dataset build | question identifier, stable across conditions |
| `question` | string | dataset build | the question text |
| `standard_answer` | string | dataset build | the gold answer |
| `language` | `"en"` or `"zh"` | dataset build | question language |
| `qtype` | string | dataset build | question type, used for breakdowns |
| `n_pdf_pages` | int | dataset build | document length |
| `gt_necessary` | list of `[page, x1, y1, x2, y2]` | dataset build | elements every correct answer must cite; the recall denominator |
| `gt_all` | list of `[page, x1, y1, x2, y2]` | dataset build | necessary plus optional supporting elements; the precision target set |
| `raw_predict` | string | inference | the model's unmodified output |
| `answer_text` | string | inference | the answer parsed out of `raw_predict` |
| `format_ok` | bool | inference | whether a parseable citation was produced |
| `pred_tuples` | list of `[doc_id, page, x1, y1, x2, y2]` | see below | the citations that get scored |
| `error` | string, optional | inference | set when the request failed; such rows are excluded as infrastructure errors |

Pages are 1-based. Boxes are `x1 y1 x2 y2` in the rendered page's pixel coordinates. The leading
`doc_id` in `pred_tuples` is always `1` because every question concerns a single document; it
exists so the matching helper can be reused unchanged in multi-document settings.

## Where `pred_tuples` comes from

This is the only structural difference between the two conditions, and it is the difference the
paper studies.

**Coordinate interface.** The model emits box coordinates directly in `raw_predict`. The parser
in `src/infer_matrix.py` reads those numbers and writes them into `pred_tuples` unchanged. The
scored geometry is the model's own.

**Language interface.** The model emits only text: an answer and a list of verbatim quotes, as
JSON. `src/match_wholedoc.py` embeds each quote and each parsed block crop of the document with
one multimodal encoder, solves a one-to-one assignment between quotes and blocks, and writes the
page and box of each matched block into `pred_tuples`. The model never produces a number that
reaches the scorer.

## Language-interface model output

`raw_predict` holds a JSON object:

```json
{
  "answer": "The internal contact pins use a beryllium-copper alloy.",
  "evidence": [
    {"quote": "the internal contact pins are fabricated from a beryllium-copper alloy"}
  ]
}
```

Quotes must be verbatim spans of a single page region, at the granularity of a sentence, a table
row, a table cell, a caption, or a note. Tables and figures are quoted through their captions,
cells, or notes, which is how non-textual evidence enters a text-only interface. Requiring
verbatim spans also anchors each quote to a specific block, since a caption or a cell is nearly
unique within a document, whereas a free-form description of a figure could match any topically
similar one under semantic retrieval.

## Cached intermediates

Not shipped, regenerated by the pipeline:

| path | produced by | contents |
|---|---|---|
| `data/citevqa/mineru_cache/` | layout parsing | parsed blocks per document, with page, box, type, and text |
| `data/citevqa/docling_cache/` | `src/cross_parser_docling.py` | the same, from the independent parser used for the cross-parser check |
| `cache/block_emb/<doc>.npz` | `src/prebuild_block_emb.py` | one crop embedding per block, with the block pages and boxes |

The embedding cache is per document, so its cost is paid once and amortized across every
question about that document.
